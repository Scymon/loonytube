## New findings

### P2 — `pages.draft_blocks` readable by anonymous users (NEW)
**Evidence:** `supabase/cms.sql:56–57` — `create policy "pages public read" on public.pages for select using (is_published = true or public.is_admin());` — combined with `supabase/cms-drafts.sql` adding `draft_blocks` (and `updated_by`) to the same table. RLS is row-level, not column-level: any anonymous client hitting the Supabase REST API can select `draft_blocks` for every published page and read the admin's unpublished work-in-progress (the app itself never selects it — `src/lib/pages.ts` selects only published columns — but the API does not enforce that).
**Impact:** Unpublished page edits (upcoming announcements, half-finished copy) leak to anyone who queries the API directly. Low severity — CMS pages are operator-authored, not user data — but it defeats the entire point of the draft/publish separation.
**Definition of done:** anon/authenticated roles cannot read `draft_blocks` — e.g. `revoke select` on the column for `anon, authenticated` + grant of the remaining columns, or move drafts to an admin-only `page_drafts` table.
**Size:** S. **Status:** new, ready.
